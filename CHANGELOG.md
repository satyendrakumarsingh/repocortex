# Changelog

All notable changes to RepoCortex are recorded here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Entries explain *why* a change was made and what failure mode it addressed,
matching the standard the commit history sets. Every measurement quoted here came
from an actual run.

## [Unreleased]

- **A compiler index is reused when the indexer's version probe times out.** The cache key includes the indexer's version, and when the `--version` probe missed its timeout on a loaded machine the key fell back to the pinned version. It then no longer matched the run whose probe answered, so a valid cached index was discarded and the indexer ran again, which takes minutes. The cache now records the reported version with the binary's path, size and modification time, and uses it when the same binary's probe fails; a changed binary is not trusted with the old version.

- **A large edit no longer blocks one answer, and eight performance gaps from an audit are closed.** (1) `serve`'s edit check re-indexes at most 20 changed files or about 2.5 s of them before answering (a C repository paid 0.45 s fixed plus 0.1 s a file: 81 files took 8.6 s, and 15.2 s on a machine under load, against 4.5 s for the first answer now); the rest are finished by a background pass that holds `reindex.lock`, the answer says `index_busy` with `refresh_pending`, and later calls report progress until it is done. (2) Dart re-export lookup (`infer/reexport.go`) indexes each key by its `/`-suffix, so an import path, including an external `package:` one that matches nothing, costs a map lookup: 6.7 us to 223 us per lookup growing with the module count before, 75 to 175 ns flat after. (3) The module resolvers (Perl, Julia, Elixir, MATLAB, CMake) build a file's directives, package blocks and run sets once per file instead of once per call (`moduleDirectivesOf` was 9.3 s of 113 s of resolve CPU on 640,000 synthetic Perl references, and `ResolveFile` as a whole 14.1 s, now 5.4 s). (4) `EnsureFileCallers` is one ordered pass over symbols and pending references instead of a nested `NOT EXISTS` per reference: 1.06 s to 0.23 s on 300 files of 300 definitions and 800 references, with the same set of callers (checked against the old query on random corpora); it was 36.6 s (32%) of the resolve CPU on the synthetic Perl repository, whose resolve went from 124 s to 79 s with (3), and its edge sets, and those of PostgreSQL's parser, this repository's `internal/` and the synthetic Dart repository, are identical before and after. `MarkResolutions` and `AddResolvedEdges` already use chunked prepared multi-row statements in one transaction; what remains of them (25 s each) is SQLite maintaining four indexes on `symbol_references`. (5) The Swift mask retry is skipped for a file with 100 or more error nodes, where it cost 15.7 s of 66 s over 65 SDK interface files and fixed nothing (66.3 s to 44.5 s, statuses unchanged); a replaced or rejected tree's arena is released at once. (6) A parse's wall-clock allowance scales with the file (4 s plus 25 ms a KiB, Haskell 3 s plus 15 ms) instead of 60 s for every file: a 120 KB file the grammar cannot read took 60 s in css, dart, ex, less, bicep, adb and make and now 7 s, a Haskell `do` block of 19 KB went from 8 s and 619 MB to 3.4 s and 538 MB, and a tree nested past 1,500 levels is recorded as partial with its reason instead of spending 28 s in the quadratic definition query (Erlang, 0.27 s now). (7) `index` runs under a default 768 MiB soft memory limit when it finds up to 64 MiB of source and `GOMEMLIMIT` is not set (`--memory-limit` or `REPOCORTEX_MEMORY_LIMIT` set another, `off` removes it): 1,114 MB to 918 MB peak RSS (-18%) at the same 15.5 s on 561 C files, while on 14,000 files and 117 MiB the limit cost 11% for no lower peak, which is why it is not applied there. The source-bytes admission budget that bounds concurrent parses already existed (`pipeline.DefaultInFlightBytes`). (8) Three fuzz findings are fixed and kept as seeds: an `extends ,` with no name no longer emits an empty supertype reference, a quoted clause word such as `"IN"` is not a table, and Unicode white space is trimmed from an ORM table name.
- **An incremental index now builds the graph a full index would.** It resolved again only the changed files and the references bound into them, so a reference elsewhere kept its old outcome: adding a file left its callers unbound (0 edges where `index --full` has 4), and removing a Dart barrel export, deleting an R `DESCRIPTION`, changing a return type or deleting a base class left stale or missing edges. Now every file whose references a change can rebind is resolved again, whatever their outcome: files bound into a changed file, files that name a definition whose signature changed, importers of an added, deleted or re-importing file (through barrels and headers), the callers of a function returning a changed type, files under a project marker that came or went, and, when a supertype relation moves, every file naming a member of the types it reaches. A body-only edit selects no names. `resolve --re-resolve` now resets unresolved and ambiguous references too, and drops only the resolver's own edges, where it used to drop every non-compiler edge (EXPOSES, PUBLISHES, CONSUMES and the rest, which nothing put back). `serve`, `watch` and the git hooks take the same path. Migration 0025 adds an index on references by receiver. An update that changed no Go file no longer type-checks the whole Go module or re-runs the Go router mounts (the check counted unchanged files as changes): a one-line edit to `install.sh` here went from 17 s to 3 s. `REPOCORTEX_PROFILE_DIR` now profiles an incremental `index` too.
- **Wrong edges found by an adversarial pass are fixed or left unbound.** (1) A local assigned from a call loses that call's return type the moment the function assigns it again, anywhere in the function (`var o = repo.make(); o = repo.other(); o.save()` bound `Order.save` at `high` in Java, TypeScript, Rust, C# and Swift), and Java overloads that differ only by parameter type and return different types give no type. (2) A private member is not inherited: in Java, C#, Kotlin and PHP a subclass's call no longer binds a base class's `private` method ahead of an interface default. (3) A PHP trait's method now overrides the inherited one (`use T` was read as a second parent and lost to `B::m`). (4) A Lua alias `require`d twice, or bound as a parameter, names no module. (5) Clojure parameters, `let` bindings and named `fn`s shadow referred names, and a `defn-` or `^:private` definition is not reachable from another namespace. (6) A C `static` function is never the target of a call from another file; one defined in a header still is. (7) A Dart `import ... as p` brings names in only through `p.`, and a `_private` name binds only inside its own library (a file and its `part`s). (8) A supertype written in a one-line class header (`class A extends B { void m() {} }`) starts at the class, not at the last method on the line. (9) A C# explicit interface implementation (`void I.M() {}`) is indexed as `I.M` and is no longer bound by an unqualified `M()`. One corrected golden edge: `Cart.total -> util.format` in the Dart fixture came from an `as u` import and is no longer bound; the Swift accumulator `sum = sum.adding(l)` is now `low` (name only) instead of `high`. **Migration:** `0024_symbol_flags` adds `symbols.flags` (private, PHP trait); files gain it on their next re-parse.
- **Seven defects found by an adversarial pass are fixed.** An empty or comment-only `.repocortex.yml` means defaults instead of `parse .repocortex.yml: EOF`, a wrong-typed key names the key and what it wants instead of a Go struct type, and an `index.exclude` glob such as `[` is rejected instead of silently excluding nothing. `analyze_patch` no longer reads SAFE beside a compile error: the stored parameter count was never read back (every definition compared as unknown, so a Go arity change was missed), a Python definition with no stored signature is now compared by its declaration line from the indexed text, and a patch the type checker rejects gets the verdict `breaks_build`, never `proven` or `SAFE`. `hooks install` from a linked worktree writes where Git reads (`git rev-parse --git-path hooks`, which honours `core.hooksPath`), `status` and `uninstall` agree, and the hook indexes the worktree whose commit ran it (`--project "$(git rev-parse --show-toplevel)"`). `search` builds its query as `search_code` does, so `a.go`, `main()`, `hello-world`, `x:y`, `AND` and `"` are searches and not FTS5 errors, and `--json` uses `file_id`, `path` and `score`. A given `-n`/`--limit` must be at least 1 on every command (`symbol -n 0` returned 20 of 30 while `search -n 0` returned all 30). With `--json` a failing command prints `{"error": {"message", "code"}}` on stdout as well as the text on stderr, and an empty `symbol` result is `[]`, not `null`. The MCP stdio server answers an empty batch and a message with no `method` with `-32600` and malformed JSON with `-32700` (id null) instead of ending, finishes answering requests already read when stdin closes, and clips any echoed token over 200 bytes. Smaller: `query` names the statement and not an upper-cased comment and explains a bare `SELECT`, a lone `\r` is a line break, a wrong `path` on `get_symbol` with one definition names that definition instead of reading AMBIGUOUS, and `docs/CLI.md` shows schema v23.
- **Two indexes can no longer destroy each other, and a damaged or foreign index is named as such.** (1) `index` (full and incremental) and `resolve` now take `.repocortex/reindex.lock`, the lock `serve`, `watch` and the git hooks already used, and reclaim abandoned runs only under it. Before, a second `index` found the first one's unfinished run, called it abandoned and deleted its rows, so the first failed with `FOREIGN KEY constraint failed` or `database is locked`. A second writer waits 30 seconds (long enough for a hook's or the watcher's short pass, short enough that a script behind a full rebuild gets an answer) and then stops with `another index is running (pid N, lock …)`. (2) An index whose schema is newer than the build (a `schema_migrations` row above the last migration) is refused by every command with "made by a newer repocortex (vN > vM) … upgrade repocortex, or rebuild with `init --force`"; it used to read as `OUTDATED`, with advice to run `index`, and `index`, `resolve` and `migrate` wrote into it. (3) A truncated, overwritten or zero-byte `index.db` is reported as corrupt with the rebuild commands, instead of `database disk image is malformed (11)`; `doctor` fails on it, and no longer prints `[ok] index`. (4) An index in a directory the user cannot write to (`chmod 555 .repocortex`) opens `immutable` and can be queried; it failed with `attempt to write a readonly database`. (5) `doctor`'s parse status counts the files `index` reports: "5 files indexed, 8 skipped (13 discovered)", where it used to print 13 as the total.
- **C and C++ `#include` rows bind.** A quoted include was recorded as the bare path (`util.h`), which is joined to no directory and keeps its extension, so it matched no file and the import tier contributed nothing: `main -> scale` in a project with `src/util.h`, `src/util.c` and a namesake `scale` elsewhere bound only at `medium` ("same directory, but the language requires an import"), and a header in another directory (`include/util.h`) never helped at all. C and C++ now read an include as CUDA and Objective-C do: the extension is dropped (`util.h` covers `util.h` and `util.c`, `.cc`, `.cpp`, `.cxx` of that stem, whichever header extension), each include is recorded as written and joined to the including file's directory with the longer match winning, and `<...>` is kept as written only. Two gates came with it, from the measurement: a same-directory function in C is now `low`, as in C++, because the only edges it gets wrong are a `static` helper of a file nobody included, which no tier can tell from a linkable one; and C++ takes a class of a neighbouring file as in scope only through an include (as CUDA), so two directories' `Stack` are told apart. Same-directory binding stays on for both languages (CUDA turned it off), because it measured as carrying far more right edges than wrong ones. On a 471-file C tree, `high` call edges rose from 32,235 to 95,566, `medium` fell from 42,866 to 3,250 and `low` from 2,241 to 953, with no edge lost; on a 519-file C tree (6 of 20,507 edges lost), `high` rose from 7,074 to 9,250 and `medium` fell from 7,394 to 485, the rest moving to `low`. New fixtures `TestCResolution` and `TestCPPResolution` (95% precision, every wrong edge `low`, stable over 20 runs).
- **Four resolution gaps in shipped languages are closed.** (1) A call to a method that a class's ancestry both implements (a class) and declares (an interface) now binds to the implementation: in `Cart extends Order implements Describable`, `$this->describe()` bound at `high` to `Describable.describe` because the interface is the nearer ancestor, though `Order`'s parent defines it. The walk now holds an interface's declaration and keeps climbing for a class that implements it, so the declaration stands only when no class does. The rule is shared, so Java, C# and Apex get it too: the same shape bound to the interface in all three before, and Apex's `super.audit()` with a base class and an interface both declaring `audit`, which was left ambiguous, now binds to the base class; no Java or C# golden moved. (2) PowerShell command names are case-insensitive: `write-log` now reaches `Write-Log`. A name with no candidates as written borrows those of the other spellings the repository defines, in path order, so a call whose own spelling exists still binds to that one. (3) In an R repository, `pkg::f()` where `pkg` is the package its `DESCRIPTION` names (the `Package:` field, recorded at indexing) binds to `f` in that package's `R/`, and not to a script's namesake; any other package stays external. (4) Dart `export 'src/x.dart';` in a barrel brings `x.dart`'s names to whoever imports the barrel, followed four barrels deep with a visited set so cycles end, and `part 'x.g.dart';` joins a generated file's names to the library that names it. An export is no longer an import of its own file, and a stem with a dot (`model.g`) is one path segment, which is why a part never matched its import.
- **MATLAB, Fortran, CUDA, GLSL, HLSL and CMake bind calls across files.**
  - **MATLAB:** a function is global by its file name, with `+pkg` packages, `private/` folders, local functions and classdef methods kept in their own scope.
  - **Fortran:** binds through `use` (with `only:`) by module name. Private module procedures are not reachable.
  - **CUDA:** reads includes as C++ does, and counts a kernel launch `k<<<g,b>>>()` as a call of `k`.
  - **GLSL and HLSL:** read `#include`.
  - **CMake:** commands bind to a `function()` or `macro()` defined in the same file or in one the caller runs through `include`, `find_package` or `add_subdirectory` (`high`), else in a parent `CMakeLists.txt` (`medium`), else the only one of that name (`low`).

  Builtins and toolkit APIs never bind to repository names. Every fixture measured 100% precision (7 to 32 edges each) and was stable over 20 runs. Main gaps: transitive includes, case-insensitive Fortran and CMake names, and MATLAB methods on values.

- **Resolution is the same on every run.** When a definition is declared in more than one file (an Objective-C method in `Item.h` and `Item.m`, a C function in a header and a source file), the resolver chose between them by symbol id. Files are indexed in parallel, so the ids, and with them the target of every call to such a method, changed from run to run (`TestObjCResolution` failed about one run in six). The choice is now ordered by file path, and by position within a file.
- **Definitions are recovered from the unreadable parts of Perl and Swift files.** Where the grammar gives up (an ERROR region), lines shaped like a definition (`sub name {`, `func name(`, `class Name`) are read as one, at `medium` confidence, and the file's parse note says how many. Measured on about 4,900 files already on this machine: only Perl (34 subs in 105 files) and Swift interface files (2,407 declarations) lose definitions this way, with no spurious ones. Every other language measured loses none, so the pass is off for them. Comments, strings, POD and forward declarations are never read as definitions.

- **A local assigned from a call takes the type that call returns.** `order = repo.find(id); order.save()` stated nothing about `order`, so `save` bound by name alone, at `medium` or `low`, or not at all. When the bound function declares a plain return type, the resolver now looks `save` up on that type.
  - **Confidence:** the edge is never stronger than the weaker of the two bindings it rests on, and never `exact`.
  - **Stated types win:** a stated or constructed type always takes precedence.
  - **What it doesn't do:** chains, `Self`, and wrappers like `Optional<T>`, `Promise<T>` or `Result<T, E>` are not followed.
  - **Languages:** Java, C#, Swift, Rust, PHP and TypeScript. Kotlin, Scala, Dart and Python are left out, for reasons recorded in the code.
  - **Measured** against `scip-typescript` on rxjs, ajv and scip-typescript's own source: the case covers about 1% of calls on untyped locals. All 21 edges it adds or raises are correct, and `high` precision did not change.
  - **Migration:** `0023_return_types` adds `symbols.return_type` and the producing call's position on each reference. Files gain the data on their next re-parse.

- **A file's top-level caller is handled everywhere it can appear.** Calls made outside every definition have had a caller since 14 November: a synthetic `(top level of <path>)` symbol, created only for files that need one (10 of this repository's 13,391 symbols). Four consumers still mishandled it, and each is fixed with a test:
  - **Test-gap analysis** failed with "target symbol not found in index" whenever one was in the blast radius.
  - **Architecture checks** could not see a forbidden call made at the top level of a file. A new registry reader returns those edges with the caller's file, and the report names the caller `(top level of …)`.
  - **Context packs** dropped the script that holds such a call, even when the call graph reached it.
  - **The portal** showed the caller as plain text; it now links to the file's page.

  Graph export, `docs`, `diff` and the runtime and dry-run readers still leave these edges out.

- **Fewer definitions lost to grammar errors in F#, Make, PowerShell, Groovy, Swift and Haxe.** Each fix is checked by a new hand-written fixture that reproduces a failure the 13 November verification recorded.
  - **Swift:** `@Sendable` and `@MainActor` before a function type no longer make the grammar give up on the enclosing class.
  - **Make:** `$(X:pat=)` no longer derails the rest of the file.
  - **Groovy:** methods and constructors with modifiers and several typed parameters are read, and so are abstract trait methods.
  - **Haxe:** object typedefs, metadata, type-parameter constraints, `enum abstract` and abstract members are read.
  - **F#:** each function of a `let rec … and …` group gets its own line.
  - **PowerShell:** DSC `Configuration` blocks are read.

  The guarded second parse that blanks unreadable text, already used for F# and Groovy, now covers Swift, Make and Haxe too. On the fixtures, recall went from 73% to 100% for Haxe, from 90% to 100% for Make, and from 96 to 99% to 100% for the rest, with no spurious definitions left.

- **Haskell, F#, OCaml, Perl and Zig bind calls across files.**
  - **Haskell:** reads every `import` form (qualified, aliased, with and without lists, `hiding`) and binds through modules.
  - **OCaml:** a file is its module, and `open`, `include` and module aliases bring it into scope.
  - **F#:** `open` and module aliases, with definitions qualified by namespace and module. The `.fsproj` compile order is not read.
  - **Perl:** reads `use`, `require` and `use parent`, and binds package-qualified calls, `->` method calls on a package, `$self` or `__PACKAGE__`, and `SUPER::`. A plain `use A::B;` is read as importing every sub of `A::B`, because export lists are not read.
  - **Zig:** binds `@import` of a file, relative to the importer.

  A bare call whose name an enclosing parameter, lambda, pattern or local binding shadows is no longer read as a call of an imported function of that name (Haskell, OCaml, F#). On multi-file fixtures every edge was correct for all five (16 to 23 edges each). Main gaps: functions passed as arguments, F# type members, OCaml local opens, and Perl methods on variables.

- **Vue, Svelte, Apex and Solidity bind calls across files.**
  - **Vue and Svelte:** script blocks were already read as TypeScript or JavaScript, and are now tiered as such. A component the script imports and the template uses (`<Foo />`, `<price-tag>`) is an `INSTANTIATES` edge to that component, including a default import under another name. Svelte `$lib/` imports resolve.
  - **Apex:** has no imports, and its classes are global by name, so a class the repository declares once binds at `high`. Standard namespaces such as `System` and `Database` are builtins.
  - **Solidity:** reads every `import` form and binds library calls, inheritance (`is`), `emit`, `revert`, modifiers and `new`.

  On multi-file fixtures, precision was 100% for Vue (12 of 12 edges), Svelte (12 of 12) and Apex (34 of 34), and 95% for Solidity (19 of 20, the wrong edge `low`). Main gaps: calls inside Vue template expressions, `<svelte:component>`, an Apex `super` call that a superclass and an interface both declare, and Foundry's own `vm` and `assertEq`.

- **JavaScript, PHP, Ruby and Rust are `typed`.** Each now has an arity dialect, published only when the parameter count is exact. Defaults, rest and splat parameters, keyword arguments and Ruby block parameters leave the count unknown, and Rust skips `&self`. Ruby `x = Foo.new`, PHP `$x = new Foo()` and Rust `let x = Foo::new()` (through `?`, `.unwrap()` and similar tails) now state the receiver's class. A receiver named after a class but declared without a stated type no longer binds at `high` by its name alone: `money = load(x); money.format()` and a loop variable `order` are `medium` in Ruby, PHP and Rust.
  - **How each was measured:** JavaScript against `scip-typescript` on npm's source (1,228 files), where 4,926 of 4,932 `high` edges were right, 99.88%. PHP, Ruby and Rust on multi-file fixtures only (46 to 51 `high` edges each, none wrong); no compiler indexer for them was available, so their real-code precision is unmeasured.
  - **Trade-off:** on Ruby's standard library about 1,060 edges moved from `high` to `medium` under the naming rule, many of them probably correct.
  - **Known defect:** in PHP, a method an interface declares and a base class defines binds to the interface declaration.

- **Groovy, Julia, Erlang and Clojure bind calls across files.**
  - **Groovy:** reads Java-style imports, including static, wildcard and aliased imports.
  - **Erlang:** binds `m:f()` to the module the file is named after, and `-import` lists. A call whose argument count contradicts the function's arity is ruled out.
  - **Clojure:** reads `ns` `:require` with `:as` and `:refer` (and `:use`), mapping namespaces to files.
  - **Julia:** reads `using`, `import` and `include`. Definitions are qualified by their module.

  Erlang, Clojure and Julia share a resolver that binds by module name. Groovy's import handling is gated so Java, Kotlin and Scala are unchanged. On multi-file fixtures, precision was 100% for Erlang (20 of 20 edges) and Clojure (18 of 18), 95% for Groovy (19 of 20) and 93% for Julia (14 of 15), each wrong edge `low`. Main gaps: Erlang `fun f/1` references and macros, Clojure record constructors, calls from a Julia included file to its module's other names, and untyped Groovy receivers.

- **Symbols for INI, Nginx, awk and four template languages.**
  - INI `[section]` headers are packages, as TOML table headers are.
  - Nginx `server` blocks (named by their first `server_name`) and `upstream` blocks are classes, and `location` blocks are functions named by their path.
  - awk functions are functions.
  - Jinja2 and Twig macros and blocks, Blade `@section`s, and Liquid `capture` and top-level `assign` are definitions.

  INI keys are not definitions, as in TOML and YAML. Dockerfile and `.properties` stay text only: the deployment and configuration analysers already report their stages, arguments and keys, and a grammar query would index each one twice. Gaps are in each language's `KNOWN_GAPS.md`; Jinja2's grammar gives tags no nodes of their own, so a tag that follows another on a new line is skipped rather than given the wrong line. 115 of the 206 grammars now have a definition query, and 91 are text only.

- **Bash, R, Elixir and PowerShell bind calls across files.** They were `parsed`; each now reads its imports:
  - **Bash:** `source` and `.` with script-relative paths, and bats `load`.
  - **R:** `source()`, and a package's `R/` directory as one namespace that testthat tests see.
  - **Elixir:** modules, `alias`, `import` (with `only:`) and `use`. Elixir has a resolver of its own, because it binds by module name, not by file.
  - **PowerShell:** dot-sourcing, `Import-Module` and `using module`. Class methods are qualified by their class.

  Builtins, cmdlets and external commands never bind to a repository function of the same name. On multi-file fixtures, precision was 100% for Bash (14 of 14 edges), R (15 of 15) and Elixir (17 of 17), and 92% for PowerShell (11 of 12, the wrong edge `low`). Main gaps: transitive sourcing in Bash and PowerShell, `pkg::f()` calls into an R package's own namespace, Elixir function captures and protocol dispatch, and PowerShell commands written in a different case.

- **Swift, Dart, Objective-C and Lua bind calls across files.** They were `parsed`: definitions were found, but no call reached another file. Each now reads its imports and has a resolver spec:
  - **Swift:** a SwiftPM module is the tree `Sources/<Target>/**`, whose files see each other without an import. `import Core` covers the module.
  - **Dart:** relative and `package:` imports name a library, and `import … as u` qualifies calls.
  - **Objective-C:** quoted `#import` names a header and its implementation file.
  - **Lua:** `require("a.b")` names `a/b.lua` or `a/b/init.lua`, and `local m = require(...)` qualifies `m.f()`.

  Framework and standard-library calls are kept off same-named repository functions. On multi-file fixtures, precision was 100% for Swift (21 of 21 edges) and Lua (10 of 10), 94% for Dart (15 of 16) and 90% for Objective-C (9 of 10). Every wrong edge was `low`. Main gaps: Dart barrel re-exports and generated `*.g.dart` parts, Swift extensions and protocol dispatch, and Lua method calls on untyped values, which stay `low`. A call bound to a type through the deferred inherited-member pass is now `INSTANTIATES`, as a direct one already was.

- **Nine more languages have symbols: Ada, Agda, PureScript, Racket, Emacs Lisp, Fennel, Janet, Prolog and Tcl.** Each has a definition query and a conformance fixture that states what counts as a definition. For example, Ada takes packages, subprograms, protected operations and types; Prolog merges a predicate's clauses into one definition; the Lisps take top-level definition forms only, never ones inside a function body; and Tcl takes procs, namespaces and TclOO classes and methods. Agda's grammar breaks on common forms (an indexed `data` declaration, a `where` block with a signature), which can lose the rest of the file; that and the other languages' gaps are in their `KNOWN_GAPS.md`. 108 of the 206 grammars now have a definition query, and 98 are text only.

- **Eight more languages have symbols: Perl, Haskell, Pascal, COBOL, Elm, Nix, Verilog and Assembly.** They were text only: their files were searchable, but `symbol`, `outline` and every graph answer found nothing in them. Each now has a definition query and a hand-written conformance fixture under `fixtures/langs/` that states what counts as a definition. Examples: Haskell merges a function's equations into one definition, Pascal takes methods declared in a class and their bodies, COBOL takes paragraphs, sections and level-01 data items, and Nix takes top-level bindings only. Forms the grammar mis-parses are listed in each language's `KNOWN_GAPS.md` (Pascal subrange and generic types, Elm operator definitions, Verilog class constructors, Assembly data labels). `.vh` is now read as Verilog. 99 of the 206 grammars now have a definition query, and 107 are text only.

- **The release job publishes the Homebrew formula.** The tap's formula was edited by hand and, after v1.0.1, still installed v1.0.0 under the old `cortex` name. `scripts/release/render-homebrew-formula.sh` renders `repocortex.rb` from a release's `SHA256SUMS`. It refuses a pre-release tag or a missing checksum, rather than write a formula that cannot verify its download. A new `homebrew` job runs it after each release and opens a pull request on `satyendrakumarsingh/homebrew-tap` that replaces `cortex.rb` and adds `formula_renames.json`, so `brew upgrade` moves existing installs to the new name. Without a `HOMEBREW_TAP_TOKEN` secret the job says so and succeeds. `update-manifests.sh` renders the same file into `packaging/homebrew/`, which holds the v1.0.1 formula. It passes `brew style`.

- **Tests that call through an interface are found.** A test written against `Store` calls `Store.save`, and that call is bound to the interface method, so the walk from `SqlStore.save` never reached the test. On a four-file Java fixture, the implementation's only test was invisible, and `untested_critical` could report the method as untested. `find_tests`, `repocortex tests` and `untested_critical` now follow a method to what it implements or overrides. They use method-level IMPLEMENTS edges where the index records them (Go), or the class's IMPLEMENTS or EXTENDS edges plus a method of the same name in the supertype (Java, Kotlin, C#, TypeScript). The tests that reach those methods are listed with the signal `interface_dispatch`, ranked below a recorded call chain and above a naming match, and capped at `medium` when another implementation exists.
- **`--path` prefers whole file names.** `callers save --path Store.java` answered for `SqlStore.java`, the first definition whose path merely contained the text, and its first line named the other one. `callers`, `callees`, `references` and `rename` now use a substring only when no candidate's path matches whole segments. For `rename` that was the difference between editing the right file and the wrong one. The error for an ambiguous name now says how to choose: a qualified name (`SqlStore.save`) or `--path`.

- **Every known issue in the roadmap is fixed.** They were found by running every command for the CLI output and portal guides.
  - `rename`: a definition site is `exact` once a compiler indexer has read its file or bound a reference to it, so the default `--floor exact` applies after a SCIP import instead of refusing every rename.
  - `plan_change` and `analyze_impact`: both use the same confidence floor and print risk as `N/100`, so the same change no longer scores 5 in one and 0 in the other. The PR comment and `impact --diff` say `/100` too.
  - `references`: a Java type named as a field, parameter, local variable, return type or type argument is now a `REFERENCES` edge to its class, so a class used only as a field type no longer reads "No references found". A type with no class of that name in the index (`String`, `List`) is ignored, not counted as a blind spot. A type named by a single-class import is bound at `high` ("the class an import names").
  - `diff`: two different refs that name the same run (an incremental update rewrites its one run) are refused, with the `git worktree` and `--from-index` commands that build the older side. Diffing the run against itself would have reported no change.
  - `compile`: configuration keys take at most a quarter of the scope while code waits. A request naming a setting filled all 12 slots with keys from environment files, which cut the class that reads them, so `verify` reported the edited file as in neither scope.
  - `config`: keys in `.repocortex.yml` and Compose files are no longer "declared and never read". This tool and Docker read them, which `--json` says as `read_by`.
  - `deps`: a Maven or Gradle dependency whose groupId is not a prefix of any import reads "cannot tell" instead of "not imported", because a coordinate does not name the packages inside it (`spring-boot-starter-web` is imported as `org.springframework.web.*`). `--json` carries `import_status`.
  - `trace`: a span joins its method by `code.filepath` and `code.lineno` (the innermost function holding the line), or by `code.function` narrowed by `code.namespace`. The old namespace test compared a dotted name with a path and never matched. Two equally good matches are reported as ambiguous, not guessed.
  - The CLI output guide's affected examples were run again.

- **`analyze_patch` takes a diff and, for Go, says what stops compiling.** Pass `diff` (a unified diff of one or more files, applied in memory to the working tree; a hunk whose context is not near the line it names is refused, not guessed) or, as before, `path` and `content`. Every file gets the definition comparison it had; for Go, the patched packages and the packages importing them are type-checked twice in memory, without and with the patch, and each error that is new with it is listed with its file, line and the compiler's message (`app/app.go:5 not enough arguments in call to lib.Total`). Errors the code already had are not blamed on the patch, and nothing is written.
- **Context packs: detail falls with distance, and the withholding rule is said once.** An item that lost its source to the pack's budget now shows its declaration line when the task names it or it is one call away; further items stay a name and a place. The reason source was withheld, a 230-character sentence that was repeated on some forty items of one pack, is a short phrase on each item and stated in full once in the notes. The self bench's packs are 7-12% smaller (8,100-8,700 tokens from about 9,300) at the same 5/5 and 100% recall.
- **What not to break, from the source.** `get_symbol`, `explore_symbol` and `plan_change` name the comments in and just above a definition that say what whoever changes it must keep: `HACK`, `XXX`, `DO NOT …`, `NOTE(…)`, `WARNING`, `SAFETY`, `INVARIANT`, `IMPORTANT`, `KEEP IN SYNC`, in capitals and inside a comment. Lines above count only as the definition's own doc block, not the end of the one before it.
- **Whether agents believe an empty answer.** Session stats count each tool's empty answers and how many the agent followed with `search_code` or by asking the same tool again (`empty_answers`, `search_after_empty`, `retry_after_empty`, and per tool `empty`/`followed_up`); the audit log marks each empty answer (`empty`) for the same comparison across sessions.
- **`coverage import` keeps the coverage, and two answers use it.** The command parsed a Go coverprofile, LCOV, Cobertura or JaCoCo report and printed a summary; nothing was stored, so no tool could say whether a test had ever run a function. It now stores, per function, method and class, how many instrumented lines ran (`--dry-run` keeps the print-only behaviour) and each file's hash at import, so a file edited since is marked stale and not counted. `analyze_impact` adds the target's covered share and the impacted callers with no covered line; `find_tests` says when the imported run never executed the target. A profile has no per-test data, so tests are not re-ranked, and nothing is added when no profile is stored. Migration `0022_symbol_coverage`.
- **README: benchmark figures that could not be reproduced are removed.** The monorepo and framework accuracy tables, the per-language Pulse table and the token-savings tables had no run, fixture or command behind them in this repository, and two contradicted its own records (gin's 98.4% against `docs/accuracy.md`'s 1,976 of 1,976; a Python recall of 91.1% against 78.9%). What remains has a command beside it: the measured tool-schema cost per profile (now 550 / 2,100 / 5,400 / 9,100 tokens for compact / minimal / standard / full, from `repocortex tool list`) and the token budget of the self bench's packs.
- **Go and NestJS routes get the prefix they are served under.** A Go service fills a router in one package and chooses its prefix in another: `users.RegisterRoutes(api.Group("/users"))`, `r.Mount("/billing", billing.Routes())`, `r.Route("/reports", reports.Register)`, or a handler's method reached through a struct field (`deps.MerchantAck.Mount`). Those routes now carry the full URL, through chains of functions that hand their router on, with packages found through each `go.mod`'s module path; a function reached under two prefixes keeps its routes as written, calls in tests are ignored, and a removed call takes its prefix with it. Within a file, chi `Route` closures (whose parameter shadows the outer router) give their routes the closure's prefix, and `rg.POST("", h)` on a known router is the group's root. On a 25,000-file repository, 13 chi routes in one service were renamed (`POST /request` to `POST /api/notifications/merchant-ack/request`). NestJS `app.setGlobalPrefix('api')` in an application's bootstrap prefixes that application's controllers; a call with options (`exclude`) is not guessed at.
- **A name a shared library also defines is not bound to the service's own.** The last-resort tier that picks the only definition in the caller's subproject now declines when a candidate in `libs/`, `common/`, `shared/` or `packages/` defines the name too: the caller most likely means the library's and lost the import that would have said so.
- **Compiler-proven edges survive an incremental refresh for every language.** Replacing a changed file deleted every edge into its symbols, including the exact edges from files that did not change, and the heuristic resolver bound those references again at `high` or `medium`; proof returned only at the next `resolve`, which runs the indexer for minutes. Go was fixed earlier by re-running the built-in type check. For TypeScript, Python, Java, C/C++ and Rust, `index`, `watch`, the hooks and `serve`'s per-request check now read the project's cached `.repocortex/scip` index again and put back only the edges from unchanged files into a definition of a changed one; the indexer is not run. A document counts as unchanged when the content hash of its file is the hash the index was built from (recorded beside each index since this version; an older index records it at its next `resolve`), so an edit that is undone makes the document trustworthy again and a modification time is never consulted. A changed file's own document is never used, since its positions describe the old text, and a definition that was deleted gets no edge. It runs only when a file of that language was modified. Measured on this repository's index (14,607 symbols, 91,482 parsed call sites): 0.8 to 1.1 s per project, once per refresh, plus a read of the index.
- **An agent's edits are in its next answer.** `serve` now checks the working tree before every answer and re-indexes the files changed since the last check, so the ask, edit, ask-again loop no longer gets the second answer from the code as it was. Answers say so: `edits_checked_at`, `refreshed_files` and `index_busy` in provenance, and `refreshed before answering: <files>` in the text; the caveat that working-tree edits are invisible is replaced by when they were checked. A check measured 0.2 s on this repository and 0.4-0.6 s on a 25,000-file one, so it runs at most every 2 s and no more often than ten times its own duration; nothing is written when nothing changed. It writes through its own handle under `.repocortex/reindex.lock`, which `--watch` now takes too, so hooks, the watcher and the check never write at once; a lock held elsewhere for over 2 s is reported, not waited out. `--check-edits=false` turns it off. The portal and `repocortex tool` do not check.
- **The last automatic re-index is reported.** A git hook's background pass has no terminal, so a failed one was visible only in `.repocortex/logs/auto-index.log` while the index quietly stopped following the code. `status` now prints `Last auto-index: <time>, ok in 1.2s` or `FAILED: <why>` (and `last_auto_index` in `--json`), and every MCP answer's provenance carries the same record. A trigger that arrived just as a pass released its lock was recorded and never acted on; the flag is now checked again after the lock is let go. `last_resolve_at` in provenance is the time the last pass finished, not when it began.
- **Hooks in `.git/hooks` name the binary by its absolute path again.** The check meant to give a committed hooks directory (`.husky`, `.githooks`) the bare name `repocortex` also caught `.git/hooks`, so every ordinary install depended on `PATH` and a git client with a minimal one skipped the hook silently. A hook's shebang is judged by its interpreter's name: `fish`, `pwsh`, `csh` and `tcsh` contain "sh" and were given a POSIX block they cannot run.
- `docs/reference/cli.md` is generated from `docs/CLI.md` (`scripts/sync-cli-reference.sh`), and a test fails when they drift; the copy had lost Next.js routes and ActiveMQ events. The indexing scale test's absolute budget is calibrated by its own half-size run, so a machine slowed by `go test ./...` no longer fails it; a change in the cost's shape is still caught by the doubling ratio.
- **Portal tables fit their frame, and a symbol's heading stays one sentence.** A path now breaks only after `/` or `_` and a qualified name only after `.`, `#`, `::` or `_`, and the explanation column may break a quoted path, so a table's last columns no longer sit past the edge behind a scrollbar macOS hides (on a 25,000-file repository a callers table needed 949px and got 350). Below 1280px wide the notes beside an answer move under it, and a table that still overflows shows a shadow on the side with more. A symbol's heading used to be the tool's whole first line whenever an answer was incomplete, because the counts pattern missed the clause between them and the risk; it is now always a sentence ("Used directly in at least 45 places … Risk is moderate or higher."), with one plain line on why and the tool's explanation folded under **Why**. Above a table the answer opens with what was found; the caveat stays in "What this answer cannot see".
- **`repocortex ui` serves the redesigned portal, and the previous portal is retired.** The portal that `ui --next` served is now the only one: five sections (Home, Explore, Change, Health, Agents) and a page for each function, type, file, route and table, every figure a call to the same tools an agent uses under `/api/v1`. The twenty-three-screen portal (`internal/web`), its Playwright suite and its CI job are deleted. It is served on loopback only: `--host` accepts 127.0.0.1, ::1 or localhost and refuses anything else, because the portal has no login. `--allow-refresh` is removed and says so (no route writes; run `repocortex index` or `repocortex watch`); `--next` and `--max-nodes` still parse and do nothing. `ui --json` no longer reports `allow_refresh`. The portal guide and its screenshots describe the new portal.
- **Context packs search each function's own text.** Full-text search ranked whole files, and bm25 favours short ones, so a long module holding the function a task is about ranked out of reach: on a 25,000-file repository a 12,000-line service module ranked 2,315th for "audit", far outside the fifty files a pack reads, and when a long file did match, all its functions carried the same evidence. Every function and method now has its own full-text row (a contentless FTS5 table, migration 0021), and a pack ranks definitions by the whole task at once and seeds the call-graph walk from the best of them. For "add an audit log entry when a task status changes" on that repository the pack now opens with the shared audit service's `log_status_change` and the service methods that call it on each status transition. Each item says which function's text matched (`… (in log_status_change)`), and an item seeded by text no longer claims to be "named by the task". Cost, measured: +4% index time and +4% index size on this repository (12.1 s vs 11.7 s; 1.5 MB of 42 MB); an existing index fills the rows on its next update, 13.7 s for 125,122 definitions and 18 MB on the 1.6 GB index above; pack latency unchanged.
- **Express cross-file router mounts (`app.use`).** Like FastAPI and Flask, Express applications declare sub-routers in separate modules (`routes/users.js`) and mount them from the application root with a prefix (`app.use('/api/v1/users', usersRouter)`). RepoCortex now joins CommonJS `require()` and ES module imports (default, named and namespace) across files and renames each route to the URL it is served at (`GET /:id` becomes `GET /api/v1/users/:id`). Middleware between the path and the router, a router required inline, routers mounted on mounted routers, and TypeScript sources imported as `./users.js` are followed. A router served under two prefixes keeps its own path, mounts made by test files are ignored, and a removed mount takes its prefix with it on the next run.
- **Interface-to-implementation caller bridging.** In frameworks using dependency injection or polymorphic interfaces (Spring `@Autowired`, NestJS `@Inject`, Go interfaces), callers invoke interface contracts rather than concrete implementations. `find_callers` now audits hierarchy relationships and notes when an implementation method implements an interface method that receives calls (or when an interface method has concrete implementations), preventing AI agents from falsely assuming 0 direct callers means a method is unused.
- **Asynchronous task queue discovery.** Added task queue extractors for Python Celery (`@shared_task`, `@<app>.task`, `task.delay`, `app.send_task`; a task with `name=` consumes both its function name and its registered name), Node/TypeScript BullMQ (`new Worker()`, and `queue.add` on a variable holding a queue, in files that import Bull), and Temporal (`RegisterWorkflow`, `RegisterActivity`, `workflow.ExecuteActivity`; in Python a `@workflow.defn` class is the workflow, started by `client.execute_workflow`) alongside Kafka, RabbitMQ, SQS, SNS, GCP Pub/Sub and ActiveMQ.
- **`coverage import` reads JaCoCo XML.** Java and Kotlin projects on Maven or Gradle write `jacoco.xml`, which was rejected or misread as Cobertura. XML reports are now told apart by root element (`<report>` is JaCoCo, `<coverage>` is Cobertura); a line is covered when any instruction ran and skipped when it has none, and package-relative paths resolve to `src/main/java` or `src/main/kotlin` files through the existing suffix match.
- **`auto-index` no longer crashes.** It ran `index` and `resolve` by calling them directly, which gave them no context; the store then opened its database with a nil context and panicked. Every managed git hook runs `auto-index`, so the index silently stopped refreshing. Measured: 2 of 4 concurrent runs panicked before, 0 after.
- **History on repositories with linked worktrees.** go-git refuses `extensions.worktreeConfig`, which git turns on for worktrees, and such a repository returned no history at all: hotspots, bus factor, owners, blame and co-change were empty (on a 25,946-file monorepo with seven worktrees). - **A non-shell hook is no longer reported as covered.** When `post-checkout` is a Python (or other) script, RepoCortex leaves it alone and writes `post-checkout-repocortex`, which git never runs by itself. `hooks status` now says the hook is not active until your hook calls that script, and `hooks install` prints the line to add.
- **Event brokers.** ActiveMQ over STOMP or JMS is recognised (go-stomp, stomp.py, stompjs, Spring JMS), and a generic `producer.send("X")` is attributed to the broker the file actually imports. ActiveMQ queue keys were being reported as Kafka topics with no consumers.
- **Next.js routes.** App Router `app/**/route.ts` exports and Pages Router `pages/api/**` handlers are reported as endpoints, with route groups, parameters and catch-alls mapped to the path.
- **`find_tests` / `repocortex tests` separate helpers from tests.** In Python test files only `test*` functions and `Test*` classes are runnable, as pytest collects them; helpers such as `_create` were listed as tests to run (83 of 803 on one symbol).
- **`serve --watch`, and answers that follow edits.** The server can keep the index current in-process, silently (stdout is the MCP transport). Independently, the server's symbol cache was keyed by run ID while incremental updates rewrite the run in place, so a session kept answering from the symbol table it loaded first; it now drops the cache when the run changes.
- **`config` is 5× faster on large repositories.** An insertion sort, a per-row secret-name test and a linear scan per usage made it take 22 s on a 26,000-file repository; it takes 4.4 s with byte-identical output. `blindspots`, which uses it, went from 34 s to 9 s.
- **Compiler-index cache follows workspace inputs.** A workspace lock file, a hoisted `node_modules`, a `tsconfig` the project extends and Gradle's settings and version catalog above the project now invalidate a project's cached index, so a dependency upgrade is not answered from an index built against the old dependencies.
- **`accuracy.indexers.max_parallel` works.** It was parsed and ignored. Above 1, compiler indexers run concurrently (installs still one at a time, results in plan order); the default stays 1, because each Node-based indexer holds its own heap.
- **No stray files after an interrupted resolve.** Files the compiler pass writes into the tree (`.vue.ts` mirrors, `pyrightconfig.json`) are recorded first and removed by the next run if a run was killed, but only while they are unchanged; mirrors never overwrite an existing file. Test-fixture folders are no longer planned as indexer projects.
- **Subproject isolation no longer splits a project at its `src/` or `tests/` folder** because a `tsconfig.json` or `requirements.txt` sits there.
- **Python routes mounted from another file carry their prefix.** FastAPI's `app.include_router(users.router, prefix="/users")` and Flask's `register_blueprint(bp, url_prefix=...)` usually sit in a different module from the routes, which were indexed without the prefix ("GET /{id}" rather than "GET /users/{id}"), so client calls to the real URL bound to nothing. `resolve` now joins each mount to the router it names through the mounting file's imports (absolute, relative and aliased; nested mounts compose), and renames the endpoint; the stored route is untouched, so a later run recomputes it. A router mounted under two prefixes keeps its own path and is counted, and mounts in tests are ignored. On a 26,000-file monorepo: 1,862 endpoints corrected in 2.3 s, client calls bound to endpoints 0 → 20.
- **Python routes in single quotes, and Blueprint prefixes.** `@app.route('/x')` was read as having no path (or, on a prefixed router, as the prefix alone); a Blueprint's `url_prefix` and a same-file `register_blueprint(..., url_prefix=)` were ignored.
- **Context packs on large monorepos keep to the code.** A test the task's words match no longer anchors the graph walk (its neighbourhood is fixtures and other tests), one test file contributes at most three units, and symbols under `docs/` no longer anchor a pack. On a 26,000-file monorepo the same task's pack went from 34 tests and 4 documentation keys of 63 items to 13 and 0 of 68; the self retrieval benchmark is unchanged at 5/5, 100% recall.
- **`compile` is 2–4× faster on large repositories.** Its impact pass reloaded the whole symbol table for each of up to three targets; it now loads it once, alongside the context pack rather than after it, with identical output.
- **Smaller fixes.** `arch adr` no longer reads a runbook with a "Status:" line or a `YYYY-MM-` filename as a decision record; `outline` reads relative paths from `--project`; `tests` and `owners` accept `--path` like `explore` and `callers`; `indexers list` names go/types for Go instead of scip-go, which never runs; blind-spot totals say when a category stopped at `--limit` ("50+", "at least 235") instead of presenting the cap as the count.

### Upgrading from v1.0.1
- **Re-index after upgrading.** The index schema is v18 (migrations 0014 to 0018, added; none edited). Opening an older index applies them. 0014 records how each file's language was decided, 0015 records what each call was made on (and whether a call that binds to nothing leaves the repository), 0016 adds an index for looking up the definitions of a name in given files, 0017 adds the per-language binding statistics that answers open with, and 0018 adds the indexes behind the per-symbol reads of an answer and the dead-code count. A row written by v1.0.1 records neither how its file's language was decided nor what each call was made on. `repocortex index` notices the build changed and re-parses every file; run `repocortex resolve` after it, which also stores the statistics. Until then a call whose receiver shape was not recorded binds at `low` at most, and an answer computes its coverage figures live, as it did before, so it is slower.
- **Hidden directories are no longer indexed**, unless they hold project automation or configuration (`.github`, `.gitlab`, `.circleci`, `.devcontainer`, `.husky`, `.storybook`, `.config` and others listed in the commit that added the rule). `.idea/`, `.vscode/`, a `.venv/` and `.claude/worktrees/` were indexed before, the last as complete copies of the repository. Hidden files are still indexed unless they are recognisably scratch (`.log`, `.tmp`, `.lock`, `.db`, editor leftovers, `.DS_Store`). `.git/` and `.repocortex/` are never indexed. To bring one back, name it in `index.include` with a pattern component that itself begins with a dot (`.claude/**`); `*` and `**` do not match a hidden name.
- **The size limit is one number, 2 MiB.** It was effectively 256 KiB, because discovery read files up to 2 MiB and the parser refused anything over 256 KiB without naming it; seven of redis's core sources are between 256 KiB and 700 KiB. Set `index.max_file_bytes` in `.repocortex.yml` to change it, between 1 KiB and 8 MiB. A file over the limit is recorded as skipped with its size, and `repocortex index` and `status` name the largest. An index written by v1.0.1 may show `source is 300000 bytes, over the 262144 limit`; re-indexing parses those files.
- **`parse_status` describes the parse, not the extraction.** `ok` means read to the end with no syntax error, `partial` means syntax errors were recovered from or the parse was stopped, `failed` means no usable tree, `skipped` means no parse was tried. Whenever it is not `ok`, `parse_error` begins with a reason token (`syntax_errors:`, `budget_exceeded:`, `stopped_early:`, `text_only:`, `too_large:`). Anything that read `partial` as "nothing was extracted" needs updating, and `Index: DEGRADED` now means a parse was abandoned: syntax errors, text-only files and oversized files no longer degrade an index. A file that a mask below had to blank part of says so in `parse_error`, also when it then parses cleanly.
- **`text_only` languages.** A language whose grammar is bundled but which has no definition query is recorded as `skipped` with `text_only:` and its text stays searchable. 115 of the 206 grammars are in this group and 91 have a definition query (`repocortex languages` prints both counts; the group was 120 of 206 before the definition queries below were written). `repocortex index` and `status` count text-only files by language. A `.txt` file is Vim help only if it carries Vim help markers; they were all reported as `vimdoc`. Any other `.txt` file now has no grammar: it is recorded as skipped (`no_grammar`) and is **no longer searchable by text**, which the `vimdoc` label had given it by accident. To keep plain-text files searchable, route them to a text-only language in `.repocortex.yml` (`index.language_overrides: {"**/*.txt": markdown}`) and run `repocortex index --full`.
- **Some files are read as another language.** The grammar now follows the file's content, its `#!` line and `index.language_overrides`, not the extension alone. An Objective-C `.m` file is no longer MATLAB, a C++ header is no longer C, `.fs` is F# and not Forth, `.pp` is Puppet and not Pascal, an extensionless script with a `#!` line is read, `.C` and `.H` are C++, and a file in a language with no grammar (Coq, MUMPS, Mercury) is skipped under its own name instead of being misparsed. Symbol counts for those files change.
- **Different symbols for many languages.** Definition queries were written or replaced for most of the languages the tool reads (72 have a fixture; see "Added"), so the symbols an index holds change on re-index. Go indexes only package-level `var` and `const`; C# no longer records a return type or `if` as a method; C and C++ no longer record a forward declaration, a function-pointer typedef's return type, a `= default` or `= delete` member, or a name that is a language keyword; Rust records `static`, associated types, inline modules and `macro_rules!`; Elixir and Erlang clauses of one function are one symbol. Documentation formats now contribute symbols: a Markdown heading is a symbol of kind `package`, a TOML table header, a YAML anchor, a JSON Schema or OpenAPI schema name and an HTML element id are symbols too, so a name lookup in a documentation-heavy repository can return a heading beside a function.
- **PHP, Kotlin and Scala now record calls,** and Java, C# and C++ record object creation. Until now these languages had definitions and no references, so `find_callers` was empty and `list_dead_code` set them aside as not judged. They are judged now, on the tiers measured in [accuracy](docs/accuracy.md).
- **An ambiguous name returns a list of candidates**, each with the `path` and `line` that select it, as an answer with the first word `AMBIGUOUS`. It used to be an `internal` error with a list of "qualified names" that every overload shares. The tools that take a symbol now take `line` beside `path` to choose a definition (a path alone could not tell two definitions in one file apart), and the relationship tools take `limit` and `offset` to page through rows. A symbol may be written `Owner.member`, `Owner::member` or `Owner#member`. A tool that is about one kind of thing (`find_implementations` is about types) says that no type of that name is indexed, instead of answering zero for a method of that name.
- **`find_implementations` lists every subtype,** direct ones first and then by depth, each with the weakest link of its path as its confidence. It used to list direct subtypes only and not say so (monolog's `HandlerInterface`: 4 listed, 69 reach it). `direct_only` (and `repocortex implementations --direct-only`) restores the old list and still counts what it leaves out. Only types are listed as subtypes; a function that holds an anonymous class extending the target is counted apart on the first line.
- **Risk can be `unknown`.** `analyze_impact` reports level `unknown`, with the counts and no score, in place of `low` when the callers could not be determined (a language whose calls are not extracted, references that were never bound). `moderate` and `high` are unchanged, since a floor survives missing evidence. `find_tests`, `plan_change`, `analyze_change` and `list_dead_code` follow the same rule. A risk computed over an analysis cut at its depth reads `low or higher`, with where it was cut.
- **Answers start with a word when the index cannot stand behind them.** `UNKNOWN`, `UNRELIABLE`, `UNVERIFIED`, `INCOMPLETE` or `AMBIGUOUS` opens the first line of a relationship answer, and the verdict never reads stronger than the coverage under it (see "Added"). A function that is passed by name, a caller hidden by the confidence floor and a subtype the extractor could not list also open the line with `INCOMPLETE`. A client that parsed the first line as a bare sentence now sees these words.
- **`INSTANTIATES` edges.** A call that constructs a type (`Account(...)` in Python, `Type.new` in Ruby where the type writes no `new`, a Go conversion, `new Widget(3)` in Java, C# and PHP, `Widget w(3);` in C++, `<Button />` in JSX) is an edge of kind `INSTANTIATES` to the type, not a `CALLS` edge. `callers` and `find_callers` read `CALLS` only; `references`, `analyze_impact`, test discovery and data-flow traversal follow both. `find_callers` now says how many constructions a type has instead of reporting none.
- **The tool list is larger.** The `full` profile has 28 tools (it had 25), `standard` 18 and `minimal` 7. The schema an agent pays for on every request, from `repocortex tool list`, is 1,972 tokens on `minimal`, 5,031 on `standard` and 8,439 on `full`; v1.0.1 measured about 1,700, 4,400 and 6,400. The three new `full` tools (`list_knowledge_risks`, `list_communities`, `get_session_stats`) and the new arguments (`path`, `line`, `limit`, `offset`, `direct_only`, `include_test_only`) account for the difference. A deployment that pinned a profile for its token budget should look at the new figures.
- **The grammar library is gotreesitter v0.57.0** (was v0.50.1). The 5-second wall-clock parse limit is gone; see "Changed".
- **The VS Code extension needs a `repocortex` binary newer than v1.0.1.** It asks about one definition by `path` and `line`, which v1.0.1 rejects as unknown arguments.

### Added
- **Every answer is graded against the coverage it rests on.** An answer could say "COVERAGE TOO LOW ... Do not present what follows as an answer" and "verdict: strong ... Act on these" together, because the gate read how much of the index was bound and the verdict read each row's tier. A relationship answer now carries a reliability (`good`, `incomplete`, `unverified`, `low`, `none`) computed from what the index did with the references spelled like this symbol, how its language resolved, and the run, and the verdict has no path to `strong` unless coverage is good and nothing was cut. `get_resolution_coverage` and the portal read the same figure. The rules are tested against every tool and carried to the REST and shell surfaces. A symbol whose own references are all accounted for is no longer called unreliable because its language binds poorly elsewhere (koa's `isStream`: five callers, exactly right, told "do not present" because 59% of the JavaScript references in the repository were bound).
- **Definitions for more languages, one query and one fixture each.** Six languages had no definition query before (Markdown, Make, TOML, YAML, JSON and HTML, which took the text-only group from 120 to 114; Angular templates, whose shipped query can only record a call and never produced a symbol, are now counted as text-only too, which makes it 115); for the rest the query replaces or extends the one the library infers. A language's definition query can now be registered from its own file, replace the query the library infers (which for many grammars names nodes the grammar does not have), and be checked against a hand-written fixture. Each entry says what is extracted; what is not is written in that language's `KNOWN_GAPS.md`. Where a commit measured a before and an after, it is given.

Cap'n Proto (structs, enums, named unions and groups, interfaces and methods, constants, annotations, `using` aliases; the inferred query named only the alias half of a `using`). Circom (templates, `main`). TLA+ (modules, operators, `INSTANCE`, `CONSTANT`, `VARIABLE`, named theorems; the inferred query matched definitions anywhere, `LET` included). Authzed (definitions, caveats, relations, permissions).
  - **Stylesheets and infrastructure.** CSS (custom properties, `@keyframes`, `@property`, `@counter-style`, `@layer`, the family of `@font-face`, top-level rule sets whose whole selector is one class or id), SCSS, Less, Bicep, CUE, Puppet, devicetree, GN.
  - **Systems and scripting.** Objective-C (`@interface`, `@implementation`, categories, `@protocol`, methods, properties, instance variables, C functions, typedefs), F#, Fortran, R, GDScript, Gleam, Odin, ReScript.
  - **Data, shaders and build files.** SQL (tables, views, materialized views, types, functions, procedures, triggers, schemas, indexes, sequences; the inferred query read plain identifiers only, and `GRANT CREATE TYPE TO x` produced a type named `TO`). Prisma (the inferred query tagged enums with a kind that does not exist and recorded every attribute function call). Move, WGSL, templ (the Go-shaped inferred query recorded result types as functions), Faust, BitBake.

  - **Documents and configuration.** Markdown headings, Make targets, macros and variables, TOML table headers, YAML anchors, JSON Schema and OpenAPI schema names, HTML element ids. Each is limited to the names a developer looks up by name; keys that repeat in every file (`name`, `version`, YAML `run`) are left to the configuration analyser. Dockerfile, XML and Angular templates have no query on purpose, and their `KNOWN_GAPS.md` holds the evidence.
  - **Declarations the inferred queries missed, replaced.** Swift (initialisers, subscripts, operators, properties, enum cases, extensions, actors, macros; enum cases were recorded as functions), Dart (constructors, setters, operators, typedefs, extensions, mixins, enum constants), Bash (top-level variables, `export`, `declare`, aliases), Elixir (guarded clauses, `defguard`, `defdelegate`, `defprotocol`, `defimpl`, `@type`, `@callback`, module attributes), Groovy (the inferred query tagged every identifier of a class, so a superclass became a class and `implements Serializable` produced a class `erializable`; Spock string-named methods, traits, Gradle tasks), Zig (top-level and member declarations, fields, enum variants, string-named tests), Clojure (the inferred query matched a `def` anywhere, including inside function bodies), OCaml (it named every `let` binding a function wherever it sat, about one symbol in six; items of the file and of its modules and signatures are read now), HCL (60% of the symbols were nested blocks such as `ingress` and `tags`; only labelled top-level blocks and `locals` entries remain, named as Terraform names them, `aws_instance.web`), Protocol Buffers (messages, services and rpcs were functions; they are classes, interfaces and methods), Vue and Svelte (the component itself, top-level state, props, `$props()` destructuring, `$:` declarations, snippets).
  - **From the second check, 12 languages.** Make is read after a line the grammar cannot parse (two micropython Makefiles had yielded nothing; the 265 Makefiles and `.mk` files of micropython give the same 2,573 symbols with and without the directive fix). Solidity gains constants, errors, constructors and state variables, GraphQL is recorded on the declaration line and without enum values, SCSS keeps mixins lost to an error, PowerShell records functions without their `script:` prefix, Erlang gains modules, types, records and macros, Zig gains the fields of a struct-file, Objective-C headers that start with `NS_ASSUME_NONNULL_BEGIN` are read, Vue and Svelte take methods only from the component's own options object, a Bash `NAME+=value` is no longer a second definition, an Elixir `@callback` with a `when` clause is found. SQL `DO` blocks are opaque to the grammar and said to be.
  - **Grammar-limited languages.** F# generic types and `member inline` (they had been fields), Groovy traits and the members after a class the grammar closed early, Swift extensions of a type that is not a name and the members of a class the grammar gave up on (Alamofire's `DownloadRequest.swift` goes from 13 to 35 of 41 definitions), OCaml items inside `include struct`, `open struct` and constrained modules (about 140 definitions in three of janestreet/base's interface files), Julia operator methods and the items of a file whose root is an error.
- **Calls and construction in languages that recorded none.** PHP, Kotlin and Scala now record plain, method, static, safe and constructor calls, supertypes and imports in the form the resolver splits. Java records `new Widget(3)`, C# `new X(...)` and `this(...)`/`base(...)`, C++ a declaration that constructs (`MutexLock l(mu);`), and Kotlin top-level properties and anonymous objects are handled. A call written `os.exists(p)` in Scala binds to the object it names through its `apply`. Measured on gson, guzzle, okio and scopt: [accuracy](docs/accuracy.md#2026-11-12-calls-in-php-kotlin-and-scala-and-new-in-java).
- **Inheritance in languages that recorded none.** `EXTENDS` and `IMPLEMENTS` edges for Ruby (superclass, and `include`, `prepend`, `extend` of a constant), C# (base lists; a class list is split by the .NET `I`-prefix convention, 274 of 275 edges on Newtonsoft.Json carry the label their target implies), Rust (supertraits, and `impl Trait for Type` from the type: ripgrep went from 0 to 125 `IMPLEMENTS` edges) and C++ (base classes, including qualified and template bases). Python records subscripted bases (`ParamType[str]`) and folds `@overload` stubs into the definition that follows. A qualified supertype keeps its qualifier, so `extends java.io.OutputStream` is the JDK's class and not a nested class of the same name, and PHP `\X` is a class in the global namespace.
- **JavaScript, TypeScript and TSX are read as their module systems write them.** CommonJS (`exports.f = ...`, `module.exports`), prototype assignment, wrapped components (`memo`, `forwardRef`, `lazy`, `styled`), exported constants and `export { X }` clauses are definitions; `require` bindings are imports; `new X()` and `<X />` are references; private `#name` members, namespaces and overload signatures (folded into the implementation) are handled. Measured on express, zod and taxonomy: call-site recall on the sampled files went from 0 to 22 of 31 sites (express), 25 to 33 of 40 (zod) and 3 to 29 of 29 (taxonomy); definitions found went from 17, 993 and 6 to 72 of 72, 1,263 of 1,263 and 50 of 50 ([accuracy](docs/accuracy.md#javascript-typescript-and-tsx-commonjs-jsx-wrapped-components-13-november-2026)).
- **Guarded source masks for what a syntax tree cannot read.** The parser reads the text as written, and nothing runs the preprocessor, so an unknown macro or an `#if` group that cuts a declaration reads as errors, and one error node can swallow every class after it. For C, C++ and Objective-C, a macro the grammar has never seen (`class LEVELDB_EXPORT Foo`, `void Compact() LOCKS_EXCLUDED(mu_) {`, a lone `FMT_BEGIN_NAMESPACE`) is overwritten with spaces of the same length; for C, C++, Objective-C and C#, in a conditional group one branch (the first that is not literally `0` or `false`) is kept and the others are overwritten the same way. No offset or line moves. The masked parse replaces the plain one only when it has no more errors, no fewer definitions, no definition named after a masked token, and loses none of the plain ones; a mask that would blank most of a file is refused (`fmt`'s `test/enum-test.cc` went from 23 definitions to 1 before that guard). The first parse of a file in these languages gets 2 s plus 10 ms per KiB before the masks are offered it (a stalled google/benchmark test file had held the 60 s ceiling and parsed in 107 ms with one macro blanked). Details and the before and after on leveldb, redis, re2, fmt and JSONKit: [accuracy](docs/accuracy.md#c-and-c-macros-in-declarations-measured-13-november-2026).
- **The same guarded mask for one construct each in F# and Groovy.** An F# statically resolved member constraint call, `(^T: (member GetAwaiter: unit -> ^A) (task))`, makes the grammar loop until the library stops it, and a Groovy doc comment on one line, `/** text */`, is never closed, so in both the rest of the file was lost. Each is overwritten with text of the same length and the file parsed once more; the result is kept only if it reads further or gains definitions and loses none. On the files of the definition check FsToolkit.ErrorHandling goes from 71 to 186 definitions (186 expected) and grails-core from 78 to 127 (127 expected), and across six repositories no definition was lost by name. The mask is refused more often than kept (kept on 24 of 163 grails-core files it was tried on) because the comment is usually not what is wrong with the file. F# stays weak on other constructs: 162 of 333 and 67 of 158 definitions on the largest files of two further projects. See the [record](docs/verification/2026-11-13/README.md#f-and-groovy-with-the-source-mask).
- **A hosted-tag mechanism for single-file components.** A Vue or Svelte script is JavaScript or TypeScript with different rules about what is a definition: `const count = ref(0)` is component state, where in a plain module a constant nobody exports is not indexed. Definitions the component patterns add are marked as the host's, so the script language's refiner no longer drops or relabels them. The `<script>` tag is matched with quoted attribute values as a unit (`generic="T extends Array<string>"` no longer cuts it short) and a script inside an HTML comment is ignored.
- **Overloads are told apart by argument count.** The parser now records parameter and argument counts for Kotlin, Scala, C# and C++ (a default value, a variable number of parameters or a spread publishes no count), and the resolver sets a declaration aside only when both counts are known and differ. If one declaration is left it is the callee; if several are left, or no counts exist, the edge is `low` at most and its reason says the name is overloaded, how many declarations there are and which was taken. Argument types are not used (see "Measured").
- **A renamed import binds through the import that declares it.** `import { A as B }` and `const { a: b } = require('./x')` bind a use of `B` to `A` in the module the specifier names, to nothing when the specifier is a package outside the repository, and to no other candidate under either name.
- **A second look for names over the candidate cap.** A name with more definitions than the cap was abandoned before any rule that reads imports, the directory or the receiver's type could see it; on VS Code every one of the 651 references to `IDisposable` stayed ambiguous. A reference the first pass leaves ambiguous is now resolved a second time over the definitions of that name in the files the source points to (its own file, its directory, the files its imports name, the files that define the receiver's type), trusting only stated evidence: an import that names the definition, the same file, the enclosing type, a stated receiver type, or the package directory. On the same sample size the new `high` edges read 30 of 30 right and the new `medium` edges 28 of 30.
- **Binding statistics are stored when the index is written** (migration 0017). Every relationship answer opens with a coverage statement computed from the whole index; on a 1.9-million-reference index that was most of the 8 to 17 seconds a `find_callers` took. `resolve`, `scip import` and the incremental update store the per-language figures, and a reader trusts them only while the run's `valid` flag is set, so a write nothing refreshed makes an answer slower and never stale. Indexes behind the per-symbol reads of an answer (0018) take a second call on that index from about 600 to about 220 milliseconds, and a dead-code scan limited to one directory reads only that directory.
- **Language conformance fixtures and a tree dump.** `fixtures/langs/` holds a hand-written source tree and the list of definitions it contains for 72 languages (three more carry only a record of why they have none), and `TestLanguageConformance` fails on anything missed and on anything extracted that is not a definition. `TestDumpTree` prints the syntax tree, the query in force and what it extracts for a file named in the environment, and the fixture guide describes the whole procedure for adding a language.
- **`repocortex bus-factor` and `list_knowledge_risks`** report, per directory or file, the smallest number of author names whose commits make up at least half of the recent commits there, the share of the largest contributor and how long ago their last change was. Names as git recorded them, never merged, never an email address. Every answer says how many commits were read and the dates they span, and that a shallow clone or a squash-merge workflow distorts the figures. `full` profile only.
- **`repocortex communities` and `list_communities`** group the repository's files by how they refer to each other. Low-confidence relationships are left out by default and counted: on this repository one wrong name match merged half the files into one community. `full` profile only.
- **`repocortex system contracts`** compares the outbound HTTP calls indexed in every member of a multi-repository system with the routes indexed in every member, and reports method mismatches, path-variable count mismatches, calls with no matching route and calls that agree only under a base path no index holds. No finding is above `high`, and each loses a tier when a member is unreadable, partial or stale.
- **`repocortex sbom` and `repocortex vulns`.** `sbom` writes CycloneDX 1.5 JSON for the declared dependencies the index holds, with the version state of each (`pinned`, `locked`, `range`, `unpinned`, `unresolved`) and no timestamp unless asked. `vulns --advisories FILE` checks them against OSV records you supply and reports `affected`, `could_not_compare` or `not_affected`, and whether the code references or imports the package (`referenced`, `imported_symbol_use_unknown`, `not_imported`). Nothing is downloaded and no advisory is built in.
- **`repocortex stats` and `get_session_stats`** report a session's usage: calls and failures per tool, the size of each answer and an estimate in tokens (bytes divided by four), and time spent. It is reported as usage and not as a saving: the one agent benchmark run found no token advantage on simple lookups. `full` profile only.
- **Team tokens.** `repocortex serve --http ADDR --tokens-file FILE` accepts several named tokens, each with a scope (a profile, optionally narrowed to named tools) and an optional expiry. `repocortex serve create-token` makes one and prints it once. A tool outside a token's scope is answered exactly like one that does not exist, on `/mcp` and `/api/v1` alike, and the audit log records the token's name and never the token. See [protocols](docs/guides/protocols.md).
- **`repocortex move`** moves one top-level Go declaration (a function, type, constant or variable with its doc comment; a method as `Type.Method`) to another file of the same package and corrects the import lists of both. A dry run by default; `--apply` writes under the protocol `rename` uses. Anything it cannot prove safe is refused with the reason, and it checks its own result by scanning the four files back into tokens.
- **A VS Code extension** in `editors/vscode` shows callers, impact, tests and implementations for the symbol under the cursor by running the installed binary, with each row's confidence tier and the tool's own caveats ahead of the results, an optional caller-count CodeLens and a status bar item for index age. See [editor extension](docs/guides/editor-extension.md).
- **Release channels and verification.** Releases are signed (Sigstore), carry build provenance and SBOMs, and attach MCP bundles; a static, non-root, scratch-based container image is published; Scoop and winget manifests and an MCP registry entry are in the repository. These start with the release after v1.0.1; [installation](docs/getting-started/installation.md) says which are available and [verifying a release](docs/operations/verifying-a-release.md) has the commands that check a download. Third-party CI actions are pinned to a commit and Dependabot moves the pins.
- **A file's language is decided by its content, shebang and overrides, not by its extension alone.** `.m` was always MATLAB, `.h` always C, `.fs` always Forth, so an Objective-C codebase produced no symbols and F# was skipped outright. `index.language_overrides` in `.repocortex.yml` routes files by glob, every file records how its language was decided (`files.detected_by`), and `repocortex languages` lists them. An upper-case `.F90` or `.C` extension is tried in lower case. See the user manual.
- **Python is typed.** Calls are resolved by the receiver's class, lexical scope and named imports. `repocortex languages` lists eight languages in the typed tier (C#, C++, Go, Java, Kotlin, Python, Scala, TypeScript: those with an arity query or a scope analysis) and six in the resolved tier (C, JavaScript, PHP, Ruby, Rust, TSX); the language counts no longer include grammars that extract nothing.
- **`list_dead_code` reports code only tests reach** (`--include-test-only`, always `possible`, never `likely`) and never calls a framework entry point likely unused: a definition spelled like a handler an HTTP route names, or one that consumes an event topic, is graded `possible` with its own reason.
- **Portal pages for a file, a route and a table** in `repocortex ui --next`.
- **`repocortex serve` stays alive on a project with no index** when a client launched it: `tools/list` returns the real tool set and each call is answered with what to do, instead of a process that died during start-up and a client reporting "server disconnected". At a terminal, and with `--http`, it still exits with the message.

### Changed
- **Code outside every definition has a caller: the file's top level.** A call in a test file's `describe(...)`/`it(...)` callback, at a module's top level or in a package initialiser is bound and had no edge, so `find_callers` could not list it and said so (honojs/hono: 171 of the 274 references spelled `header` were bound and unlisted, and the answer opened with `INCOMPLETE`). `resolve` now gives each file that has such code a symbol of kind `file` named `(top level of <path>)` and starts the edge there, whether the reference was bound by the resolver or by a compiler index. A callback nested in a named function stays with that function. It is created by `resolve` and never by `index`, is not a definition (no symbol lookup, listing, count or dead-code scan sees it; `find_callers`, `find_tests` and `analyze_impact` name it), and is removed when no edge starts or ends at it. No schema change. In a test file `find_tests` lists it as the file's top level and counts it as runnable, except in Go, where only `TestXxx` functions run.
- **A compiler's answer overrides a heuristic binding of a reference.** An imported compiler index (and the Go type check) used to settle only references the resolver had left unbound. A reference the resolver had bound by name to one definition (`c.header` bound to `HonoRequest.header`, which `Context.header`, a property holding an arrow function, is not) stays wrong until something corrects it, and an edge could only be withdrawn where one existed. The references and the compiler's occurrences of one name on one line are now paired by column, and a paired reference takes the compiler's definition; the resolver's verdict stays in `prior_resolution`, which is what `accuracy` scores. A reference the resolver bound at a position the compiler resolved outside the repository is unbound and marked as ruled out. Where the counts do not pair, a bound reference is left alone.
- **A compiler relation placed in a definition the index does not hold** (an arrow function in a callback, a nested function) or in no definition is attached to the enclosing indexed definition, else to the file's top level, instead of being dropped, where the parser also recorded a reference on that line. An import or an `export { x } from` is not one: a compiler reports those names as occurrences, and counting them would make every unused import look used.
- **A call is bound by what it was made on.** The parser reported an empty receiver for a bare call, a chained one and a qualified one alike, so the resolver weighed the callee's name against whatever the file or directory held. Hand-checked on eight public projects, that was the largest source of wrong high-confidence edges in every language: gin's `errors.New(...)` bound to gin's own `New`, about 170 standard-library calls in all; a Java local `reader` stored as a call and bound to a method `reader(String)`, 1,025 of gson's 7,199 high edges. Every call reference now records the shape of its receiver (`bare`, `name`, `value`, `type`, `path`, `scope`, `self`, `super`, `expr`) and one rule per shape binds it, each with its own reason and the tier its own measurement earned. A qualified call binds through what its qualifier names or not at all, and a call on a value whose type nothing states binds to a member, never to a free function and never to the function it is written in. 1,408 edges were judged on nine projects: `high` is 95.1% to 100% weighted on every one of them, against 54% to 100% in the record, and call-site recall rose or held (gin 59% to 89%, ripgrep 52% to 73%, zod 41% to 56%). Tables, sampled edge ids and every wrong binding the record listed: [accuracy](docs/accuracy.md#receivers-binding-a-call-by-what-it-was-made-on). Fewer references are resolved on most projects; that is the point of the change. The hand check of 13 November on 14 projects the work was not tuned on found `high` slightly lower than that nine-project figure; see "Measured".
- **A call that leaves the repository is recorded as such.** A call qualified by an import of the standard library or a declared dependency binds to nothing and is marked external, on evidence from the import table, the directory layout and the manifests. It is a subset of `unresolved`; `repocortex resolve` prints how many. A language's own library names (`format!`, `clearerr`, `toLong`, PSR-7 methods, `require` in Kotlin, a platform `Response`) do not bind to a lone repository namesake, and a supertype with a qualifier that names a package the repository does not hold is external.
- **A call binds only to code a call can denote**: a function or method in a language the caller can call. A field, a constant, a configuration key, a column and a dependency line are not candidates, so CALLS edges to something that is not a function went to 0 on every project measured. A method written in an object literal is not a name in scope, and a name-only rule no longer lets production code call a test helper.
- **A parse is bounded by work, not by a 5-second clock.** The old limit returned from the call and left the parse running, so the files that failed depended on machine load (redis lost six C files at a load of 7 and eight at 19), the abandoned parses kept their cores, and a 1.6 KB C file took 7.7 s. A parse now runs in the calling goroutine on a pooled parser and stops on the library's work limits, which give the same verdict for the same bytes at any load; the clock is 60 s, a last resort. A stopped file keeps the definitions it read and is recorded `partial` with the byte and line it stopped at. On redis, before and after on one loaded machine: 27.6 s and 27.9 s became 19.7 s and 17.1 s, peak memory 3.12 GB and 3.35 GB became 0.73 GB and 0.76 GB, and parse failures 8 became 0. The measurements, including the library versions tried, are in [performance](docs/performance.md).
- **Updates stop reading unchanged files.** A file is taken as unchanged without being opened only when the previous pass recorded it under the same build, its size and modification time match, and its modification time is at least two seconds older than that pass began; the `git status` run to stamp the commit is gone. On django, an `index` with nothing changed took 2.54 to 2.68 s and takes 0.13 to 0.21 s, and a two-file edit 3.25 to 3.39 s and now 0.83 to 1.06 s, on a loaded machine.
- **`repocortex watch` starts in seconds, prints that it is starting and can be interrupted.** On macOS it held a descriptor for every file (10,399 on django), took 17 s to over a minute, ignored Ctrl-C and lost edits saved while it started. It now holds one descriptor per directory.
- **History reads work on a shallow clone.** `hotspots`, `owners`, `find_owners` and the portal's ownership screen failed on any `git clone --depth N` checkout, which is what CI uses; they now read up to the boundary and say so.
- **`repocortex index` prints the run that was stored**, so its file, symbol and parse counts are the ones `status` prints.
- **Each answer says only what the index supports about a language.** "RepoCortex does not extract calls from C" was printed on the evidence of six C definitions in two files; it is now said of a language only when at least twenty definitions in it have no reference among them.
- **The commands say what the tools say.** `callers`, `references`, `callees`, `implementations`, `tests` and `plan-change` open with the first line of the tool that answers the same question, so the doubts an agent is shown (a function passed as a value, callers the floor left out, subtypes the index could not list, a name with no type) reach people too. `plan-change` and the diff impact report print `or higher` with the reason when the analysis is a floor.
- **The installers take the binary from where the release puts it,** and the installation page is back in line with them and with `go.mod`. `install.ps1` has not been executed on Windows by the author; its path logic is compared with the release workflow by a test, and its syntax is checked by the Windows CI job.

## [1.0.1] - 2026-11-12

The first release with published binaries. It renames the command.

### Breaking
- **The command is `repocortex`.** It was `cortex`, a name several other tools also install. The index directory is `.repocortex/`, the config file `.repocortex.yml`, the ignore file `.repocortexignore`, and the environment variables `REPOCORTEX_*`. Install with `go install github.com/satyendrakumarsingh/repocortex/cmd/repocortex@latest`. An index built by an earlier build is read as is once `.cortex/` is renamed to `.repocortex/`; the database migrations are byte for byte unchanged.
- **Tool and command names changed, with no aliases.** See "Changed" below.


### Added
- **REST endpoint beside MCP.** `repocortex serve --http` now also serves every tool as `POST /api/v1/tools/{name}`, with an OpenAPI 3.1 document at `/api/v1/openapi.json` generated from the registered tools on each request, for callers with no MCP client. It holds no handlers: each call goes through an in-process MCP client, so validation, output bounds, untrusted-content framing and the audit record are the ones MCP already applies. It sits behind the same token, `Host` allowlist and `Origin` check, and takes the token only as a bearer header. A tool's own failure is reported in the body as `is_error` with status 200, so a client that retries on 5xx does not retry "that limit is negative". `GET /healthz` answers `{"status":"ok"}` without a token and reveals nothing else. `TestRESTAndMCPReturnTheSameAnswer` compares the two surfaces byte for byte on seven tools.
- **`repocortex tool list|describe|call`** runs any agent tool from the shell by its MCP name and arguments, for agents that have a shell and nothing else. `list` prints what each tool costs a model's context per request: measured on this build, 7 tools and about 1,700 tokens on `minimal`, 18 and about 4,400 on `standard`, 25 and about 6,400 on `full`. `call` exits 1 when the tool reports a failure and 0 otherwise, including for "nothing found".
- **`list_dead_code` and `repocortex dead-code`** list definitions nothing in the index calls, graded. A row is `likely` only when it is unexported, its file parsed cleanly, no unbound reference is spelled like it, and its name appears nowhere in the indexed code outside its own definition. That last check exists because the first version listed every MCP handler in this repository as unused: each is passed to a registration call as a value, which leaves no call edge. Comment-only lines are not counted, since a doc comment opens with the name it documents. Everything else is `possible`, with the reason, and is not shown unless asked for. Languages the index parses without binding references are not judged, and the count is printed.
- **`list_hotspots` and `repocortex hotspots`** rank files by commits times size over recent history and list, for each, the files usually committed with it. Where no call or import connects them, that is a dependency `analyze_impact` cannot see. Files with no definitions (bundled assets, generated text) are left out unless `--all-files`: on this repository a 550 KB bundle otherwise outranked all source.
- **`trace_call_path` and `repocortex path`** return the shortest routes from one symbol to another, each hop with its file, line and confidence. **`find_implementations` and `repocortex implementations`** return a type's hierarchy in both directions. **`find_callees`** gives agents what `repocortex callees` already gave people, and **`repocortex tests`** gives people what `find_tests` gave agents. The five new tools are on the `full` profile only, so `standard` stays the size its users chose.
- **`analyze_change`** gives agents what `repocortex impact --base --head` gave people: the symbols a commit range touched, the tests that reach them, and everything else within reach. A pull request arrives as a branch, not as a symbol, and until this an agent had to work out the changed symbols itself. An unknown revision and a directory that is not a repository are answered as guidance, not as failures.
- **`find_owners`** gives agents what `repocortex owners` gave people: who has recently changed the code a change to a symbol reaches, so a reviewer can be suggested from evidence. It returns names and never email addresses: the answer goes into a model's context, and an address has no use there. A test asserts no `@` reaches the output.
- **`repocortex query`** runs one read-only SELECT against the index, for a question no command answers. Other tools offer a graph query language here; the index is SQLite, so this offers SQL. The connection is read-only, only a single SELECT or WITH statement is accepted (which keeps ATTACH and PRAGMA out), rows are capped and the query has a timeout. It is for people and is deliberately not an agent tool: a tool is a contract, and this would freeze the schema as one.
- **Agent benchmark, round 1**, in `docs/BENCHMARKING.md`. Ten runs: finding the direct callers of five uniquely named functions, with and without RepoCortex. Both arms were correct every time (51 of 51) and cost the same within 1%. It shows no advantage on that task, and says so.
- **Audit log.** `repocortex serve --audit-log FILE`, or `REPOCORTEX_AUDIT_LOG`, appends one JSON line per tool call on any surface: time, surface, tool, arguments (cut at 2 KB), duration, outcome and answer size. It records the call and never the answer, and the file is created mode 0600. It is deliberately not a `.repocortex.yml` key: a repository must not be able to switch off the record of what an agent read from it.
- **Session instructions and three prompts.** The MCP initialize result now carries under 900 bytes of guidance naming only tools the active profile exposes, and the server offers `plan_refactor`, `analyze_change` and `get_oriented` as prompts.
- **`repocortex ui --next`** serves a redesigned portal: five sections in place of twenty-three screens, and one page per symbol with its callers, callees, reach, tests and type hierarchy as tabs. It has no data routes of its own; every figure is a tool call to `/api/v1`, so a page and an agent cannot disagree. Loopback only, same-origin only, no inline script or style. Both themes are held to WCAG AA by `TestThemesMeetContrast`, which caught a control border at 2.92:1. The current portal is unchanged and remains the default. Guide: `docs/guides/portal-guide.md`.
- **Scale suite** in `tests/scale`. It runs in the default test run at 5,000 symbols and at any size on request, and asserts that every tool's answer stays under the 24 KB inline limit, that scans do not retain memory in proportion to what they read, and that time grows no worse than linearly. Measured at 250,000 symbols and 1.26 million relationships: every answer under 24 KB, an unused-code scan in 4.2 s retaining 1.1 MB, indexing linear at about 375 files a second. Figures and method: `docs/operations/scale-testing.md`.
- **`repocortex serve --http host:port`** serves MCP over Streamable HTTP, for clients that accept only a remote server (ChatGPT developer mode, Android Studio). Stdio stays the default. Every request needs a bearer token, from `REPOCORTEX_MCP_TOKEN` or generated per run into `.repocortex/mcp-token` (mode 0600, never printed), sent as `Authorization: Bearer` or as the last path segment for clients that only take a URL; the listen address must be loopback unless `--allow-remote` is passed; `Host` and `Origin` must name this machine or a host given with `--allowed-host`, which blocks DNS rebinding and calls from web pages. The index stays read-only.
- **`repocortex install` configures 30 coding agents** in the format each one documents, prints the exact step for agents configured through their own UI or command (`--list`), creates `AGENTS.md` guidance, and writes a CLI block to `CONVENTIONS.md` for Aider, which has no MCP.
- **`repocortex rename <old> <new>`** renames a symbol at its definition and every resolved reference, for the case where an agent or a person today edits a rename by hand from a plan and misses or mis-edits a site. It is a dry run by default. `--apply` writes only when every site is at the floor, which is `exact` (compiler-proven) unless `--floor high` is passed (that prints the measured 86.8-96.1% precision before applying), the file is unchanged since indexing, the identifier is unambiguous on its line, the file is a writable regular file inside the project root, and the new name is not already defined in an edited file; otherwise it writes nothing, lists every failing site and exits 2. Files are written atomically with the hash re-checked before each replace and restored if a later write fails; one edit runs per project root at a time, behind a `.repocortex-edit.lock` that is never stolen (a stale one is reported with its path for you to delete). Afterwards a task contract is written to `.repocortex/rename-contract.json` and `verify` runs on the changed files. Exit codes: 0 applied and verified, 1 error or verify failure or incomplete rollback, 2 refused with nothing written, 3 applied but not verified complete. Because RepoCortex never compiles, an apply that leaves the old name anywhere in an indexed file lists those lines under `LEFTOVER OCCURRENCES` and exits 3, never 0; unbound references and interface implementations without an edge are not renamed, and every run says to build and test.
- **`repocortex indexers pins`** prints the pinned compiler indexers (name, version, channel, reference, digest) from the binary alone, as a CI cache key that changes exactly when a pin does; `repocortex indexers install --out-dir DIR` writes the `.scip` files to a known, empty directory instead of a random temporary one.
- **Compiler-backed gate.** The change-safety workflow installs the pinned SCIP indexers and imports their facts before `impact`, caching scip-go on the pin table, so the blast radius walks `exact` edges wherever a compiler exists. Without it the gate's blast radius was heuristic everywhere. The step is an upgrade, never a requirement: it never fails the job, degrades to heuristic edges with a `::warning::`, lists every skipped language and its reason in the step summary, and never passes `--allow-repo-build`, so fork pull requests run only pinned, digest-verified indexers with a read-only token. `REPOCORTEX_ACCURACY: fast` turns it off.
- **Proven share of the blast radius in the PR report.** The summary row and a "How much of the blast radius is proven" table show the share of `impact`'s reached symbols that are `exact`, `high` and `medium` (interface-dispatch-only symbols are not counted; unrecognised values appear as `unlabelled`), and say so when none of it is compiler-proven, so a reviewer cannot read a heuristic blast radius as a proven one.
- `registry.EdgeHit.EvidenceCol` exposes the stored evidence column, documented as a hint.
- **`repocortex report sarif|pr`** renders the JSON from `arch`, `missed` and `impact` as a SARIF 2.1.0 file for code scanning or as one bounded Markdown pull-request comment that starts with a sticky marker. Each input is shape-checked, findings with no file are counted rather than dropped, repository text is escaped, and the comment is capped at 60000 characters.
- **Change-safety gate v2.** The shipped workflow now collects findings, uploads SARIF under the category `repocortex`, and posts or edits a single pull-request comment before it enforces `arch` and `missed`, so a failing build still explains itself. It needs `pull-requests: write` and `security-events: write`; fork pull requests get no comment.
- **"Indexing in progress" answers over MCP.** During a first index every tool now says the index is still being built, instead of "no index has been built" (which sent agents to start a second index), and an answer from a committed run adds a note when a newer run is being built.
- **Event topology, blindspot audit, refactor plans, pruning and diff minimization.** `repocortex events` maps producers and consumers of Kafka, RabbitMQ, SQS, SNS and Pub/Sub topics; `repocortex missed` audits unresolved calls, untested entrypoints, unmapped endpoints, orphan tables and undeclared config; `repocortex plan-change` emits an ordered refactoring plan with preconditions, affected tests and post-checks; `repocortex prune` reduces a file to its declarations; `repocortex diff-minimize` compresses a unified diff. The MCP server exposes `plan_change`, `list_blindspots`, `get_file_outline` and `minimize_diff`; event topology is CLI and portal only. Prisma joins GORM, JPA and SQLAlchemy as a mapped ORM.
- **Portal screens for events, blindspots and refactor planning**, a Command Palette (`Cmd+K`) and a symbol inspector drawer.
- **The code map: Graph, Tree, Treemap and Code views of one index.** The portal's graph screen now has four views behind one breadcrumb and one tab strip, sharing the map's address (`container`, `level`, `sel`), so a symbol selected in one view is the one selected in the others. The Tree lists every directory (the map draws the 48 largest) and loads files and symbols as they open; the Treemap shows where the code is, sized and coloured by a measure; the Code view shows a file's indexed text with its declarations, callers and callees, and the lines relationships cite. It reads the new `GET /api/source`, which serves only text the index holds, from the full-text copy taken at index time: there is no filesystem read, so no path outside the index can be reached. Canvas tools gained words and pressed states in place of emoji, and the layout is a select kept in the URL.
- **In-memory CSR graph.** `graph.New(db, graph.WithCSR())` answers `Traverse` from a compressed-sparse-row snapshot of the committed run, loaded on first use and replaced when the committed run changes. `repocortex serve` and `repocortex ui` enable it; library and CLI one-shot paths keep the SQL traversal. A parity test pins identical nodes, depths and confidences.
- **`repocortex resolve` imports an `index.scip` found in the project root or `.repocortex/`**, upgrading matching edges to `exact`. The outcome is always printed (and under `scip` in `--json`), and `--no-scip` opts out.

- **`repocortex missed --fail-on <severity>`** exits non-zero when a blindspot at that severity or worse exists, so the audit can gate CI. The change-safety workflow now builds the call graph (`resolve`), checks `doctor --verify-index`, enforces `arch --fail-on` and `missed --fail-on`, and prints the pull request's blast radius in the job summary.

### Fixed
- Two query plans that read every relationship in the run once per row when the database held no statistics, both found by running at size: the hotspot structure query (did not return in two minutes on a 19,000-relationship index) and the unused-code query (8.5 s at 5,000 symbols, now 36 ms). ### Security

- **`get_file_outline` no longer reads arbitrary paths.** The MCP tool read whatever path an agent supplied (path traversal, including `../` and absolute paths). It now reads through `os.Root` anchored at the project, and sensitive files (keys, credentials, environment files) are suppressed rather than outlined.

### Changed
- **Tool names follow one form**, `<verb>_<noun>` with a closed list of eight verbs chosen to match what other MCP servers and language servers already use: `get`, `list`, `find`, `search`, `trace`, `analyze`, `plan`, `minimize`.   PHP.** `c_sharp` sat in the `resolved` tier on the fallback spec, which
  declares no interop, so a `.cs` reference could bind to a Go or Python
  definition. Ruby, Rust and PHP had separators and no idea what a test file
  looks like, so `repocortex verify` answered "not a test" for every `spec/` and

  request could see; the suite needed an indexed repository on the developer's
  machine. A fixture tier that ships with the repository now drives it on every
  pull request — 149 passed, 23 skipped on the ci tier — with traces uploaded
  on failure.
- **"Not drawn", in visible text.** A relationship row on a graph card can
  point at an entity the level did not draw; that fact lived only in a hover
  title, which a phone, a screenshot and a screen reader never see. The row now
  says so, the level's omission note counts them, and a symbol card whose edge
  count and drawn rows differ states both populations, on a scope line that
  wraps, so they add back up.
- **Keeping the index current: `repocortex hooks install`.** Writes a Git
  post-commit hook that re-indexes after each commit, so the portal and any
  connected agent describe the commit you just made rather than the one you made
  on Tuesday. A stale index is worse than no index because it looks current.
  The hook is written inside markers: an existing `post-commit` is appended to,
  never replaced, and `hooks uninstall` removes exactly the marked block. It runs
  detached and swallows every failure — a hook that can fail a commit is a hook
  people delete. Measured on a real repository: the commit itself took 0.79s and
  the re-index completed behind it.
- **Refreshing the index from the portal: `repocortex ui --allow-refresh`.** Off by
  default, and the default is the point. The portal's security claim is that
  pointing a browser at localhost cannot make RepoCortex do anything, so without
  the flag the write route is *never registered* — read-only is enforced by the
  absence of a route rather than by a check inside a handler that a later edit
  could reorder. With the flag, a refresh must carry a header that a cross-site
  form cannot set and that `fetch` can only add behind a preflight this server
  never approves; a foreign `Origin` or `Sec-Fetch-Site` is refused even so, and
  refreshes are serialised so two indexers cannot write one SQLite file.
  `GET /api/indexstate` reports provenance, refresh state and hook status.

- **MCP server (`repocortex serve`).** Serves the index to coding agents over
  stdio. The database is opened read-only, so an agent session cannot mutate the
  index it is querying. Tool count is treated as a performance constraint rather
  than a preference: every exposed tool's schema enters the agent's context on
  every request, so the `minimal` profile ships six tools and a test fails if
  that grows past eight. `--list-tools` prints the exposed set without starting a
  server.
- **Bounded, framed MCP responses.** Whole files are never returned. Bounding is
  enforced centrally rather than per tool, because a bound each tool implements
  for itself is one a tool will eventually forget. Repository content arrives
  labelled `SOURCE EVIDENCE` with an explicit note that it is data, not
  instructions, because indexed source may have been written by someone other
  than the user.
- **Two honesty properties in MCP output, enforced by tests.** An empty caller
  list is not presented as proof — the index resolves only part of any
  repository, so every empty relationship result carries the unresolved and
  ambiguous counts. And the confidence *and reason* for each binding reach the
  agent: "receiver type matches" is the difference between a fact an agent can
  weigh and one it must take on trust.
- **Graph traversal (`internal/graph`).** Level-synchronous BFS — one query per
  depth level, not per node. Confidence is tracked along each path, so "reachable
  at depth 3 through a low-confidence edge" stays distinguishable from a proven
  chain. Benchmarked at 100k symbols / 500k edges: depth-3 traversal p95 2.9 ms
  at 1k nodes, 86.5 ms at 50k. `MaxNodes`, not depth, is what keeps it
  interactive.
- **Reference resolution (`repocortex resolve`).** Binds extracted references to
  their definitions, building the call graph — the question every downstream
  capability depends on. Five confidence tiers, each ruling out a specific way of
  being wrong: same file, receiver-type match, same directory, single import
  match, unique name only. Measured at **840 ns per reference**, so a
  531k-reference repository resolves in under a second. On the payment fixture it
  reconstructs `handleCallback -> updateStatus -> {save, findById}` from source.
- **Persisted references and imports (migration 0002).** Resolution needs the
  complete symbol table, which does not exist until every file is parsed, so it
  is inherently a second pass. Persisting means re-resolution — after the
  resolver improves, or once a SCIP index arrives — costs no reparsing.
- **Filesystem watcher (`repocortex watch`).** Debounced, coalesced change sets. It
  reconciles before watching, because files change while the watcher is not
  running and starting from a stale index would leave those edits invisible until
  the affected file happened to be touched again. Verified live: modify, add and
  delete on a running watcher updated the index in 102 ms, 14 ms and 2 ms.
- **Observability (`internal/observe`).** All 13 metrics, off by default, 2.85 ns
  and zero allocations per span when disabled. Attributes go through typed
  constructors and a validator that panics in tests, so a file path or a secret
  cannot reach a span — telemetry from a private repository must never carry its
  contents.
- **Error taxonomy (`internal/errs`).** Eight kinds over stdlib wrapping.
  Retryability is the one that earns its keep: SQLite `BUSY` is transient, a
  corrupt index is not, and callers can now tell without string matching. Driver
  codes are matched structurally, so the package stays a leaf with no driver
  dependency.
- **Soak suite (`tests/soak`).** Build-tagged so it never slows the normal suite.
  Watcher endurance, directory churn, index/query concurrency, and digest
  stability across 110 passes. It reports trends rather than only passing — a
  soak test whose only output is `PASS` teaches nothing.
- **M0 foundations.** Apache-2.0, CI across three operating systems plus a
  CGO-free build matrix, versioned and checksummed migrations, two-trust-domain

- **M1 source indexing.** Discovery with full gitignore semantics, content

Verified on spring-petclinic-rest: a re-index leaves `git status` clean and the cache lands beside the index.

### Fixed

- **Foreign keys were off on 97% of connections.** SQLite pragmas are
  per-connection; `db.ExecContext("PRAGMA foreign_keys = ON")` configures one
  connection out of eight. `ON DELETE CASCADE` silently did not fire, and the
  verification query passed because it reused the connection it had just
  configured. A 30-second concurrent soak produced 1,010 dangling symbols and 505
  orphaned FTS rows that later abort indexing outright. Pragmas now go in the DSN
  so every connection gets them, and verification samples 32 goroutines
  concurrently — because a single-connection check is precisely what failed to
  catch this.
- **Java constructors were stored as `function`, not `method`.** Found by
  differential testing against the C tree-sitter runtime — a bug the pure-Go
  suite could not see, which is the entire argument for building that test.
  Overlapping patterns tagged constructors twice and deduplication sorted by
  kind, so `function` won alphabetically.
- **Missing symbol kinds recovered by per-language supplements.** Java
  `@interface`, TypeScript abstract classes, method and abstract-method
  signatures, generators, and Python module-scope constants were extracted by no
  grammar. Also: `gotreesitter` ships zero explicit tags queries — all 206 are
  inferred, and the Go query silently dropped type, const and var declarations.
- **camelCase was unsearchable.** FTS5's `unicode61` tokenizer treats an
  identifier as one opaque token, so a search for `callback` could not find
  `handleCallback`. Fixed with an `expanded` shadow column holding
  identifier-split text; the original text is kept so `snippet()` still returns
  real source.
- **`.git/**` matched `.git` itself**, because `**` spans zero or more path
  components. Git internals would have been indexed.
- **A byte-length check let single-character noise tokens into the search
  index.** U+0130 is two bytes but folds to the single character "i". Found by
  fuzzing in four seconds; the failing input is committed as a seed.
- **`store.OpenMemory` used `cache=shared`,** meaning every in-memory store was
  the *same* database. Tests would have contaminated each other intermittently.
- **Pooled parser arenas were never released.** `gotreesitter` holds them as
  strong Go references until drained, so peak memory became the sum of every parse
  rather than the largest few. Draining is now conditional on heap size — an
  unconditional periodic drain measured 17% lower peak for 80% worse throughput,
  because it discards warm parser state while memory is perfectly healthy.
  Additionally, pooled `Tagger`s hold arenas outside the library's own pool; a
  10,896-file run showed 3 GB held that way.
- **The sink context outlived the worker context.** `database/sql` rolls back a
  transaction as soon as the context it was created with is cancelled, so passing
  the internal cancellable context to the `Sink` would have silently destroyed the
  rows just written and failed the caller's `Flush` with `ErrTxDone`.

### Security

- **Repository config cannot cause execution.** `.repocortex.yml` is
  attacker-controlled the moment someone clones an untrusted repo, so it may
  describe what to index but never what to run, download, or whether secrets are
  redacted. Execution fields do not exist on the repository config type, and
  unknown keys are a **parse error** — so hostile fields do not merely fail to
  apply, they fail loudly. Guarded by `TestRepoCannotSetExecutionSettings`, run
  by CI as a named security gate.
- **Repository excludes are additive and cannot be negated,** so a repository
  cannot un-exclude `.git` or `node_modules`. Negated exclude patterns are
  discarded rather than coerced, because rewriting `!**` as `**` would honour the
  letter of the rule while handing a repository a way to blank its own index.
- **Symlinks are never followed,** and links resolving outside the root are
  recorded as `symlink_escapes_root` so the attempt stays visible. A repository
  committing a symlink named `config.go` pointing at `/etc/passwd` would
  otherwise have its target hashed, indexed, and quoted back by an agent.
- **Irregular files are never opened.** Opening a committed FIFO blocks until a
  writer appears, which would hang the indexer indefinitely.
- **Fuzz targets on everything reading untrusted input** — ignore-file matching,
  pattern compilation, parsing, identifier tokenisation, and SCIP index framing.
  215k parser executions and 1.3M tokenizer executions clean at the initial
  import.

### Verification gates

Each has been observed *failing* on an injected defect, not only passing. A check
only ever seen passing is not evidence of anything.

- **Determinism** — index twice, compare the registry digest. Stable across
  1/2/4/8 workers, and *sensitive* to a single added symbol. A digest that never
  changed would pass the stability half while detecting nothing.
- **Incremental == full re-index** — the digest after add/modify/delete/rename
  equals a full re-index, so incremental updates cannot drift from ground truth.
- **Graph invariants** — `doctor --verify-index` catches dangling edges, orphaned
  symbols, cross-run edges and unproven `exact` claims.
- **FTS5 dependency guarantee** — pinned per platform, because
  `modernc.org/sqlite` enables FTS5 through an undocumented codegen flag.
- **Migration tests** — fresh, upgrade, interrupted, and edited-migration.
  Shipped migrations are immutable; an edited one is a hard error.
- **CGO-free build matrix** — all five release targets cross-compile from one
  machine and the full suite passes with `CGO_ENABLED=0`, so `go install` works
  everywhere and contributors need no C toolchain.

### Not yet implemented

Stated plainly rather than implied: SCIP orchestration (M3) — no compiler-backed
indexer is provisioned or run, so no edge currently carries `exact` confidence
and all three accuracy modes produce the same heuristic result; the context
